# Session guide

Prerequisites: packages, dependency versions, and vulnerability identifiers. Introduce CVE, package ecosystem, affected range, project applicability, and the difference between a source report and extracted metadata. Introduce the constructed Python-service adoption scenario in `student/activity.md`. Cases A-C supply contrasts, not additional dependencies of that service. A short conditional claim can model how to reason from supplied fields without giving complete case answers.

| Minutes | Activity |
|---|---|
| 0-8 | Vocabulary, four prompts, and instructor model |
| 8-20 | Case D adoption memo; contrast evidence needs with Case A |
| 20-35 | Paired analysis of Cases B and C; challenge and response |
| 35-50 | Debrief and justified revision |
| 50-65 | Independent unfamiliar case if separately available, then reflection |

For a 50-minute version, shorten pair discussion and debrief. For 75 minutes, add inspection of the grouping rule and more discussion. If no unfamiliar case is available, use the last block for independent comparison and reflection; do not describe this as a transfer assessment.

Ask: Which conclusion is supported? Which information would affect the action? Are repeated reports independent evidence? What exactly does the grouping rule count? What changes between Cases A and D?

Distinguish urgency of investigation from certainty of exposure. Reward justified alternative recommendations, including prompt investigation. Do not reward blanket dismissal or a generic request for more information. Check whether students target the limitation: component identity for questionable extraction, proposed version and use for applicability, and preservation of distinct evidence for grouping. A version outside the stored range does not certify absence of other risks. Keep initial and revised memos for formative feedback. A future research evaluation would require suitable consent/review arrangements and an independently scored unfamiliar task; this package contains no student data.
