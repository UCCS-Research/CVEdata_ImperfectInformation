# Activity

You are an engineer on a team building a Python service that retrieves information from external URLs. A teammate proposes adding `requests`, but the version and credential-handling configuration have not been chosen. Before adopting the component, the team asks for a recommendation based on Case D. Identify what to verify and explain whether to proceed conditionally, defer adoption, or investigate an alternative. This is a constructed teaching scenario, not an observation about a real project.

Read the supplied records in `data/cases.json` or `data/cases.csv`. Use the decision memo to connect claim, evidence, uncertainty, and next action. Cases A-C contrast other evidence limitations; do not assume these unrelated components belong in the same service. No dependency inventory has been supplied.

1. Individually write a brief adoption memo for D1, then explain how A1 would change the evidence you request first.
2. In pairs, examine B1-B3 and C1-C3. Each partner challenges an inference or offers an alternative interpretation. Respond using the supplied fields.
3. Revisit one memo. Explain any change in the recommendation, or why retaining it is justified.
4. Identify what evidence you would need next and how it would affect the recommendation.

For Case C, inspect the exact grouping rule in `analysis/original_unique_view.sql`. Describe the entity being counted and explain what trimming whitespace would change. The task can be completed without executing SQL.

The instructor may supply an unfamiliar record from an existing, separately held collection for independent practice. No transfer record or learner outcome is included in this release.
